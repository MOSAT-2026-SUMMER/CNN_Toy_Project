Reference paper: Yun et al., "Design and Implementation of an Alcohol Intoxication Detection System Using CNN and GRU Models," APJCRI 2023

Recreating the paper, scoped for two people and one semester

The paper's pipeline is YOLOv4 (detect) → CNN (extract) → GRU (temporal) → binary output, served through a small web page. Your goal is the same shape — video in, drunk/sober probability out, wrapped in a local app — but you don't need to reproduce every engineering choice they made. This guide walks through each decision point and what to build first.

01

Architecture: paper's pipeline vs. a simplified one

The paper trains three models: YOLOv4 (object/face detector), a CNN feature extractor, and a GRU sequence classifier. That's a lot of surface area for a semester project with two people. Here's what each piece is actually doing, and where you can cut scope without changing the core idea of the project.

What YOLOv4 is doing in the paper

YOLOv4 is a real-time object detector — given a frame, it draws bounding boxes around objects and classifies what's in each box. In this paper it's used to locate the person's face/head in each frame so the CNN only sees the relevant region, not the whole background. Training a detector like this from scratch requires bounding-box-labeled data (x, y, width, height for every object in every frame) — a heavier and different kind of labeling than the drunk/sober label you already have per video.

the actual job

Strip away the specific model names and the pipeline is really just: (a) find and crop the face → (b) extract visual features → (c) track how those features change over the 10 seconds → (d) classify. YOLOv4 is one way to do step (a) — not the only way, and not the part the paper's contribution is really about (their contribution is the CNN+GRU combination for temporal reasoning).

Recommendation

Use a pretrained face detector purely as a cropping step (not something you train), then feed the crops into your own CNN (ResNet18 transfer learning) + GRU — the exact pattern already discussed for the emotion project, just with a binary head instead of 7-class. This keeps the part of the paper that's actually novel (CNN+GRU temporal reasoning) and drops the part that's a separate research problem (training a detector).

03

Data pipeline: raw video → trainable sequences

Right now you have raw videos, unsplit. This is the first concrete coding task, and it's a good one to split between the two of you (e.g. one person writes frame extraction, the other writes the face-crop + resize step).

Step by step

  1. Frame extraction. Sample frames at a fixed rate — the paper used 10 fps over 10-second clips (50 frames/video). Match that or go coarser (e.g. 5 fps / 25 frames) if training time becomes a bottleneck.
  2. Face detection + crop. Run each frame through the pretrained detector (MediaPipe), crop to the face bounding box with a small margin.
  3. Resize. The paper resized to 64×64 because they trained their CNN from scratch. Since you're doing transfer learning from a pretrained ResNet18, resize to 224×224 instead — that matches the input size ResNet18's ImageNet weights expect, so the pretrained features stay meaningful.
  4. Sequence assembly. Group each video's frames back into an ordered sequence (shape [T, 3, 224, 224]) — this is what feeds the GRU as one time series, not individual frames as independent samples.
  5. Labeling. Video-level label (drunk = 1, sober = 0), same label applied to the whole sequence — matches the video-level labeling approach already used for the emotion project.
watch out for

The paper reports a real limitation worth planning around early: accuracy dropped substantially under makeup (~40%) and bright lighting (~50%), versus ~87%+ under normal conditions. If your recording setup can control lighting and ask participants not to wear heavy makeup during capture, you'll avoid inheriting that same failure mode.

04

Model: CNN + GRU (binary head)

Same shape as the two-phase ResNet18 fine-tuning approach already scoped for the emotion project — train a new head first, then unfreeze layer4 at a lower learning rate. The GRU sits on top, consuming the per-frame feature vectors as a sequence.

import torch
import torch.nn as nn
import torchvision.models as models

class DrunkSoberNet(nn.Module):
    def __init__(self, hidden_size=128, gru_layers=1):
        super().__init__()
        backbone = models.resnet18(weights="IMAGENET1K_V1")
        backbone.fc = nn.Identity()          # drop classifier, keep 512-d features
        self.backbone = backbone
        self.gru = nn.GRU(input_size=512, hidden_size=hidden_size,
                           num_layers=gru_layers, batch_first=True)
        self.head = nn.Sequential(
            nn.Linear(hidden_size, 64), nn.ReLU(),
            nn.Dropout(0.3),
            nn.Linear(64, 1)                 # raw logit; use BCEWithLogitsLoss
        )

    def forward(self, x):                    # x: [B, T, 3, 224, 224]
        B, T, C, H, W = x.shape
        x = x.view(B * T, C, H, W)
        feats = self.backbone(x)              # [B*T, 512]
        feats = feats.view(B, T, -1)          # [B, T, 512]
        _, h_n = self.gru(feats)              # h_n: [layers, B, hidden]
        out = self.head(h_n[-1])              # final hidden state -> logit
        return out.squeeze(-1)

Use nn.BCEWithLogitsLoss since this is binary (drunk vs. sober) rather than the 7-way CrossEntropyLoss from the emotion project.

05

Local app: Streamlit

Streamlit gets you a working local web UI in under 50 lines — good fit given the app is supporting context, not the main deliverable.

import streamlit as st
from src.preprocessing import video_to_sequence
from src.model import DrunkSoberNet
import torch

st.title("음주의 정석 — Drunk/Sober Check")

model = DrunkSoberNet()
model.load_state_dict(torch.load("checkpoints/best.pt", map_location="cpu"))
model.eval()

uploaded = st.file_uploader("Upload a ~10s video", type=["mp4", "mov"])
if uploaded:
    with open("temp.mp4", "wb") as f:
        f.write(uploaded.read())
    seq = video_to_sequence("temp.mp4")        # -> tensor [1, T, 3, 224, 224]
    with torch.no_grad():
        prob = torch.sigmoid(model(seq)).item()
    st.metric("Drunk probability", f"{prob:.3f}")
    st.progress(prob)

This mirrors the paper's own web output (a probability score, shown for both a sober and a drunk example) — you're just serving it through Streamlit locally instead of a custom web backend.
